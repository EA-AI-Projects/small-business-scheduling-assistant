# Domain docs

This is a single-context repository. Read the root `GLOSSARY.md` when it exists, and relevant ADRs in `docs/adr/` when they exist. Create these files as domain terms or decisions are resolved; their current absence does not block work.

Accepted product and technical decisions currently live in `doc/PRD.md`, `doc/HLD.md`, `doc/ARCHITECTURE.md`, and `doc/SCHEDULING_CONTRACTS.md`. Read the relevant sections before changing behavior. Use glossary terms in issues, code, and tests. Surface any conflict with an ADR or accepted decision before changing it.
